# CS 300 Portfolio Reflection

The two projects addressed the same advising problem from different angles. The program needed to read course records, show the courses in alphanumeric order, and find a course with its prerequisites. In Project One, I compared a vector, a hash table, and a binary search tree for those tasks. That made the choice of data structure more concrete for me. A hash table can make individual lookups quick when its chains are short, but it does not keep the courses in order. I chose a binary search tree because an in-order traversal can print the course list in course-number order without sorting it for every request. Project Two turned that design into a C++ program.

Parsing the file took more thought than I expected. A course with no prerequisites is valid, while a row missing its course number or title is not. I also had to check prereq how I approach a program. I now think about invalid input and the work each operation must do before settling on a structure. In Project Two, I kept parsing, validation, tree insertion, searching, printing, and cleanup in separate functions.
